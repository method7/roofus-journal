This log carries on from the afternoon of 16 November, which ended with
15 emails sent and 17 letters waiting to be posted.

## What we did

- **Recorded replies.** A business that replies is now marked as replied
  with the day and Simon's note. From then on nothing more is drafted,
  sent or called for it. When the six-month clean-up is built, it will
  keep it.
- **Wrote session logs from the merged work.** Simon asked for each log
  to list what actually changed. I now have a written routine for it and
  a script that lists every piece of work merged since the last log
  (merged means Simon approved it and it joined the main copy of the
  code). This is the first log written that way.
- **Tidied where the data lives.** Simon found the leads data in one
  folder and older copies in another and asked for it all in one place.
  Everything now lives in one private folder beside the code, never
  inside it. Simon moved the data over with one command, which checks
  that every file copied correctly, then deleted the old folder. My
  agents are now blocked from reading any private folder at all.
- **Asked for a web page.** Simon asked for something friendlier than
  typing a command for every step. I suggested two options. Simon chose
  a web page that runs on Simon's Mac only (decision 0026). Simon had
  seen some design add-ons recommended on social media and asked me to
  look into them, then chose not to use them. The page takes its look
  from method7.co.uk instead.
- **Built it in two stages.** First the foundation: the page itself, its
  safety checks and an overview of what's waiting. Then the screens, two
  or three at a time. Each was built by one of my agents. I checked
  every one against its issue and simplified it where I could before
  Simon merged it.
- **Seven screens.** The overview. Find, for searching Google for new
  businesses, then checking and preparing them. Review drafts, where
  each draft is marked ready or set aside. Send, for the day's batch:
  printing the letters, opening the emails in Mail and logging what
  went. Replies, for recording an answer. Calls, where each phone number
  is a link that opens FaceTime or a phone. A page for each record. Only
  one job is still a typed command: reading websites for missing
  details.
- **Brought the guides up to date.** Simon asked for every instruction
  to be in the guide, so it now covers each step with both its command
  and its button.
- **Posted the letters.** Simon printed and posted the 17 letters, then
  logged them on the Send screen once its buttons worked (see below).

That makes 32 businesses contacted and waiting to hear back: 15 by email
and 17 by letter.

## What went wrong

- **Every button on the page was refused.** When Simon pressed "Log
  every letter in the pack", the page said the request came from another
  website. A privacy setting on the page told the browser to hide where
  each request came from. The page's own safety check then couldn't tell
  the request was from itself, so it refused. None of the records
  changed. Every screen had passed review, because every test and every
  check I ran filled in that detail by hand. None of them pressed a real
  button in a real browser. One of my agents fixed it. I pressed a real
  button in Chrome to prove it, both with the fix and without.
- **I broke the page's styling file twice when combining work.** Screens
  built side by side each changed the end of the file that sets how the
  page looks. Twice, when I combined the changes, a closing bracket went
  missing, which can break the look of everything after it. Both times I
  found it by counting the brackets and rebuilt the file from the two
  versions.
- **I gave Simon wrong advice once.** I told Simon to throw away two
  edited files on Simon's Mac. They were part of a newer copy of the
  shared house rules. I corrected the advice. The next merged change put
  the finished copy in place.
- **Commas before "and" kept slipping into what I wrote.** The house
  style check caught each one before it went anywhere.

## What I learned

- **Press a real button in a real browser.** Tests and screenshots
  showed the page worked. A browser showed it didn't. I've written it
  down as a rule for my reviews of any page with buttons.
- **Give work built side by side its own files.** The second round of
  screens got in each other's way much less than the first, because each
  screen had its own file and added to shared files only at the end.
- **A one-click yes can be right.** One of my agents made every answer
  on the Find screen ask twice. In review, I made "Confirm" one click,
  as on Review drafts, because the page showing the evidence is already
  the check. Anything that can't be undone still asks.
