This log starts on the afternoon of 14 November, where the last one stopped.

## What we did

- **Finished drafting.** Simon merged the step that drafts each email and
  letter from Simon's approved wording, then checks it before Simon sees
  it. A letter greets a named person only when the name comes from a
  source we can trust, with the page and date it was checked. If the
  spelling might be wrong, the draft uses the business's name instead.
  Nothing can be sent by the code. Simon sends.
- **Gave the leads agent its keys.** An API key is a private code that
  lets a program use another company's service, so it has to be guarded
  like a password. The leads agent needs three: Companies House, Claude
  and Google Places. Simon put them in one private file outside my
  repository and one of my agents built the code that reads it (decision
  0017). My agents never open that file and no key is ever shown. Simon
  asked for this to work for other people one day. That is parked as an
  issue for later.
- **Tightened the shared house rules.** They now stop agents reading key
  files. Copying the new rules into my repository is waiting on Simon,
  because only Simon may change my agents' settings file.
- **Built the finding step.** It asks Google for local businesses in the
  area from decision 0013: 20 miles around Salisbury, as 15 postcode
  districts. It leaves out chains and any business already on file.
- **Read Google's terms and changed the plan.** A business's name and
  address from Google Maps must not be saved. Google does allow its place
  ID to be kept: its own code for each place on the map. Simon chose to
  keep only that and take every name and address from Companies House or
  the business's own website (decision 0018). Simon chose no terms or
  privacy policy, because only Simon uses the tool. Contact details found
  by hand now come only from a business's own website or Checkatrade,
  never Which? or TrustATrader, whose terms allow personal use only. Simon
  also raised the limit to 40 paid searches a run.
- **Made room for sole traders.** They aren't on Companies House, so
  none of them could go on file. Simon agreed to confirm each one by hand
  from its own website, to count professional registers as sources and to
  stop letters greeting a business in capitals, as Companies House writes
  names (decision 0019).
- **Read the registers' terms before building.** The osteopaths' register
  forbids using its names and addresses for commercial purposes. The
  physiotherapists' register can't find a business at all. So that part
  wasn't built.
- **Stopped using the osteopaths' register altogether.** The same terms
  covered something the business check already did: it took clinics'
  addresses, contacts and the osteopath who runs each one from that
  register. Simon chose to stop (decision 0020). One command lets Simon clear
  the register's details out of older records.
- **Published each decision on method7.co.uk** once Simon merged a
  website update.
- **Replaced the typing.** On 15 November Simon found typing each sole
  trader's details too slow. It also only suited one kind of business.
  Simon asked for the lookup to read the business's own website and
  propose each record, for Simon to accept or reject with one key. It
  keeps the web address the site gives for itself. One of my agents is
  building it now. Decision 0021 will replace the by-hand part of 0019.
- **Started a spending budget on Google.** Places, the service the
  finding step uses, wasn't in the budget's list yet, because nothing had
  used it. Simon will set the budget, with a daily limit, after the first
  test.

Nothing has been sent to any business. No live search has run yet.

## What went wrong

- **I put commas before "and" in the keys code.** The building agent
  checked only its own files and reported that everything passed. The
  automatic checks on the pull request failed. It now checks every changed
  file and waits for those checks to finish.
- **I spent too long on where the keys file sits.** Simon wanted to move
  on to the next part. Simon pulled me back.
- **I built some of it myself.** My job is to plan, send my agents and
  review what they bring back. Simon corrected that.
- **My brief for one website update got decision 0017's title wrong.** I
  fixed it before Simon merged.
- **Decision 0019's first draft added a condition.** It said Simon
  approved the registers "as long as their terms allowed it". Simon set no
  condition. The terms check came from the task. Review caught it.
- **I didn't follow my own lesson.** The last log says "Read the terms of
  every source". The business check had been using the osteopaths' register
  without anyone reading its terms. It took the work on decision 0019 to
  find out.
- **Confirming by hand was too slow.** It was built and merged before
  anyone tried it.
- **I told Simon to pick the Places service for the budget.** It wasn't
  in the list.

## What I learned

- **Read the terms before the code, every time.** Today's terms changed
  what the finding step keeps, which directories are used and whether a
  register is used at all.
- **A check is only as good as what it covers.** Checking your own files
  is not checking the change. The pull request's own checks have the
  final say.
- **Try a step by hand before it is built.** A few minutes typing one
  sole trader's details would have shown it was too slow.
- **Report what the person said, not a tidier version.** Adding a
  condition Simon never set changes the decision.
- **Do my own job.** Planning, briefing and reviewing is mine.
  Building is my agents' work.
